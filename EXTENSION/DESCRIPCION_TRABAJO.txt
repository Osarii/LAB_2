TRABAJO DE EXTENSION - BASE DE DATOS RELACIONAL
================================================

RESUMEN EJECUTIVO
-----------------
Trabajo academico completo sobre diseño e implementacion de una base de datos
relacional para un sistema de tienda en linea. Incluye investigacion teorica,
diagrama entidad-relacion y script SQL ejecutable.

CASO DE USO: TIENDA EN LINEA (E-COMMERCE)
------------------------------------------
Sistema que gestiona:
- Clientes y sus cuentas
- Catalogo de productos con categorias
- Proveedores de productos
- Pedidos realizados por clientes
- Detalles de cada pedido
- Pagos realizados
- Informacion de envios

ESTRUCTURA DEL TRABAJO
----------------------

PARTE I - INVESTIGACION TEORICA (4 paginas)
Cubre 9 temas fundamentales de bases de datos:

1. Modelo Relacional
   - Definicion de entidad, atributo, tupla, relacion
   - Ejemplo practico aplicado a cliente y producto

2. Tipos de Llaves
   - Llave Primaria (PK): Identifica unicamente
   - Llave Foranea (FK): Establece relaciones
   - Llave Candidata: Podria ser PK
   - Llave Compuesta: Multiple atributos

3. Tipos de Relaciones (con ejemplos)
   - Uno a Uno (1:1): Cliente - Historial
   - Uno a Muchos (1:N): Categoria - Producto
   - Muchos a Muchos (N:M): Pedido - Producto

4. Participacion y Cardinalidad
   - Cardinalidad minima y maxima
   - Relaciones obligatorias vs opcionales

5. Relaciones Recursivas
   - Entidad que se relaciona consigo misma
   - Ejemplo: Empleado supervisa Empleado

6. Integridad Referencial
   - ON DELETE CASCADE: Elimina registros hijos
   - ON DELETE SET NULL: Establece FK a NULL
   - ON DELETE RESTRICT: Impide eliminacion

7. Restricciones SQL
   - NOT NULL: Campo obligatorio
   - UNIQUE: Valores no se repiten
   - CHECK: Validacion de condicion
   - DEFAULT: Valor por defecto

8. Normalizacion (1FN, 2FN, 3FN)
   - Evitar redundancia y anomalias
   - Ejemplos antes y despues

9. Notaciones DER
   - Chen: Rectangulos y rombos
   - Crow's Foot: Simbolos en lineas (-, N)

PARTE II - DIAGRAMA ENTIDAD-RELACION
------------------------------------
8 Entidades conectadas logicamente:

CLIENTE
  - id_cliente (PK)
  - nombre, email (UNIQUE)
  - telefono, direccion, ciudad, pais
  - Relacion: 1:N con PEDIDO

CATEGORIA
  - id_categoria (PK)
  - nombre (UNIQUE)
  - descripcion
  - Relacion: 1:N con PRODUCTO

PROVEEDOR
  - id_proveedor (PK)
  - nombre_empresa (UNIQUE)
  - contacto, email, telefono
  - Relacion: 1:N con PRODUCTO

PRODUCTO
  - id_producto (PK)
  - nombre, descripcion
  - precio (CHECK > 0)
  - stock (CHECK >= 0)
  - FK: id_categoria, id_proveedor
  - Relacion: N:M con PEDIDO

PEDIDO
  - id_pedido (PK)
  - FK: id_cliente
  - fecha, estado (CHECK)
  - subtotal, impuesto, total
  - Relacion: 1:N con DETALLE_PEDIDO, PAGO
  - Relacion: 1:1 con ENVIO

DETALLE_PEDIDO (Tabla Intermedia)
  - PK Compuesta: (id_pedido, id_producto)
  - FK: id_pedido, id_producto
  - cantidad, precio_unitario, subtotal
  - Relacion: N:M entre PEDIDO y PRODUCTO

PAGO
  - id_pago (PK)
  - FK: id_pedido
  - monto (CHECK > 0)
  - metodo_pago (CHECK IN lista)
  - fecha, referencia, estado
  - Relacion: 1:N con PEDIDO

ENVIO
  - id_envio (PK)
  - FK: id_pedido (UNIQUE - relacion 1:1)
  - transportista, numero_seguimiento
  - fechas, estado, costo
  - Relacion: 1:1 con PEDIDO

RELACIONES IMPLEMENTADAS
------------------------
1:N  Cliente → Pedido
1:N  Categoria → Producto
1:N  Proveedor → Producto
1:N  Pedido → Pago
N:M  Pedido ⟷ Producto (via Detalle_Pedido)
1:1  Pedido → Envio
